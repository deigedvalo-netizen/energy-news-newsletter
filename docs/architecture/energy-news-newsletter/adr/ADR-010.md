# ADR-010: Issue authored by the scheduled task, published only through a gate with strict number checks

- **Status:** SUPERSEDED
- **Feature:** energy-news-newsletter
- **Requirements:** FR-14, FR-15

## Context

The owner wants a newsletter written automatically each day from the gathered news. Three placements were evaluated: (a) an LLM call inside the Python pipeline via LLMPort; (b) a Claude scheduled task that writes an issue file which CI validates before publishing; (c) a Claude scheduled task that pushes finished HTML straight to gh-pages. Option (c) gives the LLM unchecked publish authority; option (a) works but was not what the owner asked for and adds long-form generation spend to every scan run.

## Decision

Adopt (b). The task reads one immutable feed snapshot, writes issues/YYYY-MM-DD.md in a fixed template recording feed_sha256 and prompt_version, and never publishes. IssueValidator checks every number and URL against the snapshot's allowed-token sets plus disclaimer and advisory-language rules, and only PUBLISHED issues reach the site. This mirrors the pipeline rule that a judge gates every handoff. SUPERSEDED on 2026-09-16 by ADR-017 (author may read linked articles; unverified numbers warn instead of reject).

## Consequences

Positive: readable daily prose with no path for invented numbers, sources or advice to reach readers; issues are reproducible against their snapshot. Negative: legitimate phrasing like 'two sessions' or derived percentages not present in the snapshot will be rejected, so the prompt must tell the author to quote numbers exactly as the snapshot formats them; a rejected day shows the previous issue.
